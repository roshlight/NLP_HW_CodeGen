# Эксперименты и участие агента

## Постановка

Цель: обучить encoder–decoder Transformer с нуля на официальном наборе
SlavaYus/tinysms_qa_12m. Ограничения пользователя: около 107 млн параметров,
контекст 256, H100 через расширение Jupyter в VS Code, отсутствие чужих
чекпойнтов и артефактов прошлых экспериментов. Первая посылка использует 64
токена генерации, исправленная версия того же чекпойнта — до 256.

В основе реализации адаптирован код из другого проекта пользователя.
Это повторное использование исходного кода, а не весов, токенизатора или данных.
Новый BPE обучен только на официальных обучающих данных этой работы.
Подготовлено 11 774 212 обучающих и 11 912 валидационных примеров;
обучающие таргеты содержат 905 249 515 токенов.

## Инициализации в рамках этой работы

1. Свежая инициализация, LR 4e-4: численная деградация около шага 1500.
2. Новая инициализация, LR 1e-4: на шаге 2000 validation NLL 0.90784,
   доля синтаксически корректных программ 0.99219, ограниченная арифметическая
   диагностика 0.10156. К шагу 3000 обучение снова деградировало.
3. Диагностика собственных сохранённых тензоров этих неудачных запусков на CPU
   обнаружила рост cross-attention logits примерно до 43 000
   (Q RMS около 114, K RMS около 57). Добавлена RMS-нормализация Q/K
   в каждой голове до RoPE и записи в cache, включая cross-attention.
   Число параметров осталось 106 977 792. Веса и состояние оптимизатора
   полностью переинициализированы; неудачные веса не использованы для обучения.

Итоговый запуск использует LR 1e-4, Q/K-нормализацию, BF16, batch 64
и накопление 4 микробатчей. План после калибровки — 77 474 шага,
лимит времени обучения — 5 часов. На шаге 10 000: validation NLL 0.33725,
syntax-valid 1.0, арифметическое совпадение на диагностике 0.421875.
Эти числа получены до окончания обучения и не являются финальным результатом.

## Проверки

До запуска выполнены 18 тестов на H100 и BF16 preflight полной модели.
В том числе проверены эквивалентность cached decoding и teacher forcing,
отсутствие утечки будущих токенов, инвариантность к padding, градиенты chunked
loss, точное восстановление оптимизатора в тестовой модели, переобучение
малого батча. Регрессионный тест увеличивает Q/K-проекции в 10 000 раз:
выход attention сохраняется в пределах допуска, градиенты остаются конечными.

Локальная арифметическая диагностика — ограниченный AST-интерпретатор,
не официальный sandbox. Неподдерживаемые программы учитываются отдельно.
Тестовые ответы не использовались для обучения или создания новых таргетов.

## Тестовые вопросы и формат посылки

Источник — официальный split test датасета, указанного в задании:
data/test/test.parquet на закреплённой revision. Карточка набора описывает
его как 1919 вопросов проекта без эталонных программ и численных ответов.
Файл проверен по SHA-256 8bde59c8d8bb7edc4e8a503be22fc132c4a47773025d333432e78c5489e6522a.
Все 1919 вопросов уникальны; самый длинный занимает 200 токенов с EOS.
JSONL создан в исходном порядке строк parquet, без сортировки или фильтрации.
Отдельный файл Telegram-бота не получен и не сравнивался с этим тестом.

Внутри инференса батчи сортируются по длине для сокращения padding, затем
ответы возвращаются к исходным индексам. Проверка сравнивает каждый вопрос
и ответ с детальной записью инференса. На выходе только поле code,
одна программа на каждую из 1919 строк. Исходная версия использует жадное
декодирование до 64 токенов, исправленная — до 256.
Статистика синтаксиса и EOS для этого файла приведена в итоговой таблице;
она отличается от тренировочной диагностики с лимитом 256 токенов.

## Использование агента

Агент подготовил и адаптировал код, конфигурации, тесты, воспроизводимый запуск,
собственный токенизатор, мониторинг H100 через VS Code Jupyter, диагностику
численной деградации и исправление Q/K-нормализации. Агент также готовит
пакет для сдачи, генерацию JSONL и проверку порядка вопросов.
Основное влияние агента — ускорение реализации и выявление причины
неустойчивости до финального обучения. Дополнительные обучающие данные,
дистилляция и предобученные компоненты не применялись.

## Ограничения

Для первой посылки пользователь сообщил public pass@1 47.71% (458/960).
Для исправленной посылки с лимитом 256 результат бота пока неизвестен.
Фактический замер всех 1919 ответов на NVIDIA T4 пока отсутствует.
Лимит генерации 64 токена может обрезать длинные программы; текст модели
не дополняется и не исправляется после генерации.

## Исправление обрезки при генерации

После результата первой посылки проверены детали инференса: только 1029 из
1919 программ дошли до EOS на лимите 64. Среди синтаксически разобранных
программ 596 не содержали return в solve. Лимит генерации увеличен до 256;
веса, токенизатор и входные вопросы остались теми же.

Для новой посылки использован полный вывод, уже автоматически сохранённый
на H100 до получения обратной связи бота. Переобучение, подстановка эталонных
значений и исправление отдельных тестовых программ не выполнялись.
На лимите 256 получены 1918 синтаксически корректных программ, 1913 EOS
и 5 программ без return среди разобранных. Полный инференс занял 8.85 с на
H100. Эти показатели характеризуют завершённость кода, а не pass@1.
Ошибки математической интерпретации этим изменением не устраняются.
